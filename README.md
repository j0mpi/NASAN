# NASAN

NASAN (NU Laguna Scholarship Assistance Navigator) is a scholarship discovery assistant. Users submit natural-language scholarship questions in the React client, and the Flask backend classifies the request, extracts relevant student information, and returns matching scholarships.

## Project Overview

The repository is split into two applications:

- `client/`: React 19 and TypeScript frontend built with Vite and Tailwind CSS.
- `server/`: Python Flask API with rule-based intent/entity extraction, scholarship eligibility matching, and optional LLM extraction.

The normal request flow is:

1. The user submits a question through the client search bar.
2. Vite proxies `/api` requests to the backend at `http://localhost:5000`.
3. Flask handles `POST /api/chat`.
4. The backend routes simple greetings and farewells directly; other messages go through the rule-based extractor by default or the LLM when `USE_LLM=true`.
5. Eligibility requests are matched against `server/scholarships.json`.
6. The client displays the backend reply and zero or more scholarship cards.

## API

### `POST /api/chat`

Request body:

```json
{
	"message": "I am a 3rd year BSIT student with a GWA of 1.75"
}
```

Successful responses have this shape:

```json
{
	"intent": "ask_eligibility",
	"entities": {
		"gwa": 1.75,
		"year_level": "3rd",
		"program": "BSIT",
		"student_type": null,
		"affiliation": null
	},
	"reply": "I couldn't find a match with what you shared. Try adding your GWA, year level, or program.",
	"results": [],
	"source": "rules"
}
```

`results` is always an array. Each scholarship result contains its name, minimum GWA, year-level restrictions, program restrictions, employment or affiliation preference, required documents, and deadline.

Other backend endpoints:

- `GET /health`: returns `{ "status": "ok" }`.

## Setup and Running

### Backend

From the repository root:

```powershell
pip install -r requirements.txt
python server\app.py
```

The API listens on `http://localhost:5000` by default. Set `PORT` to use another port.

LLM mode uses Groq's OpenAI-compatible API. Copy `server/.env.example` to
`server/.env`, add your Groq API key, and use environment variables such as:

```text
USE_LLM=true
LLM_API_KEY=gsk_your-key
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_MODEL=openai/gpt-oss-20b
```

Never commit `server/.env` or share its API key. If a key is exposed, revoke it
in the Groq console and create a replacement.

### Frontend

In a separate terminal:

```powershell
cd client
npm install
npm run dev
```

Available client scripts:

- `npm run dev`: start the Vite development server.
- `npm run build`: type-check and create a production Vite build.
- `npm run lint`: run ESLint.
- `npm run preview`: preview the production build.

The Vite development server proxies `/api` to the backend at `http://localhost:5000`, as configured in `client/vite.config.ts`.

## File Summary

### Repository root

- `.gitattributes`: enables automatic text-file detection and LF line-ending normalization.
- `.gitignore`: ignores logs, dependency directories, build output, local files, and editor metadata.
- `README.md`: this project overview, setup guide, API description, structure, and file reference.
- `requirements.txt`: Python dependencies for the optional LLM integration and the original FastAPI/Uvicorn setup. The current Flask entry point also imports `flask` and `flask-cors`, which should be added to this file for a fresh backend installation.

### Client configuration and entry files

- `client/package.json`: defines the frontend package metadata, React/Tailwind/Vite dependencies, and development, build, lint, and preview scripts.
- `client/package-lock.json`: npm lockfile containing the resolved frontend dependency tree.
- `client/index.html`: Vite HTML entry point; defines the page metadata, favicon, root element, and `src/main.tsx` module entry.
- `client/vite.config.ts`: enables the React and Tailwind Vite plugins and proxies `/api` requests to the Flask server.
- `client/eslint.config.js`: configures ESLint for TypeScript, React Hooks, React Refresh, and ignored build output.
- `client/tsconfig.json`: root TypeScript project configuration that references the app and Node/Vite configurations.
- `client/tsconfig.app.json`: TypeScript settings for browser and React source files, including strict unused-code checks and JSX support.
- `client/tsconfig.node.json`: TypeScript settings for the Vite configuration and Node environment.
- `client/.gitignore`: ignores local environment files such as `.env` for the client project.
- `client/README.md`: the original Vite-generated React and TypeScript starter documentation.

### Client source

- `client/src/main.tsx`: mounts the React application into the HTML root using `StrictMode` and imports global styles.
- `client/src/App.tsx`: owns chat state, sends messages to `/api/chat`, stores assistant replies and scholarship result arrays, and renders chat messages and scholarship cards.
- `client/src/types.ts`: defines request, message-role, chat-message, and scholarship-result TypeScript types.
- `client/src/index.css`: imports Tailwind CSS.
- `client/src/App.css`: contains leftover Vite starter CSS for the original demo layout and theme variables; the active interface primarily uses Tailwind utility classes.

### Client components and assets

- `client/src/components/Navbar.tsx`: renders the NASAN header and brand color bar.
- `client/src/components/SearchBar.tsx`: provides the controlled chat input, trims and validates submissions, and sends messages through the supplied callback.
- `client/src/components/ScholarshipCard.tsx`: renders one scholarship's name, eligibility fields, and required-document list.
- `client/src/assets/hero.png`: image asset from the original frontend starter template.
- `client/src/assets/react.svg`: React logo asset from the Vite starter template.
- `client/src/assets/vite.svg`: Vite logo asset from the Vite starter template.
- `client/public/favicon.svg`: SVG favicon referenced by `client/index.html`.
- `client/public/icons.svg`: SVG sprite containing social and documentation icon symbols from the starter template.

### Server

- `server/app.py`: Flask application entry point. Defines `/api/chat` and `/health`, handles validation, routes simple intents, selects rule-based or LLM extraction, finds eligibility matches, and returns the unified response shape.
- `server/router.py`: lightweight regex router for greetings, farewells, and simple affirmations that do not require extraction or matching.
- `server/entity_extractor.py`: rule-based parser that detects intent and extracts GWA, year level, program, student type, and affiliation from user text.
- `server/eligibility_matcher.py`: loads `scholarships.json` and applies GWA, year-level, program, and affiliation checks to return matching scholarship objects.
- `server/scholarships.json`: scholarship and discount catalog, including eligibility requirements, required documents, and deadlines.
- `server/prompts.py`: system prompt for optional LLM mode; defines the expected JSON intent/entity output and includes representative examples.
- `server/llm_client.py`: asynchronous OpenAI-compatible client that sends the prompt and user message to the configured LLM and parses its JSON response.
- `server/package-lock.json`: empty npm lockfile generated in the server directory; the backend itself is Python-based and does not use Node packages.

## Notes

- Rule-based extraction is enabled by default. Set `USE_LLM=true` only when the LLM environment is configured.
- The client expects `reply` and `results` in every successful chat response and renders cards only when `results` contains at least one scholarship.
- Scholarship data uses mixed GWA scales: percentage values for some incoming-student scholarships and CGWA values for continuing-student scholarships. The matcher currently treats both as higher-is-better numeric thresholds.
